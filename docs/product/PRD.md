## 1. 产品目标

面向对江苏文化感兴趣的公众和内容创作者，提供按城市与主题探索文化内容、浏览文化动态、发布文化作品的入口。管理员可以维护已有新闻内容。平台以可查找、可浏览、可参与为核心体验。

本 PRD 将**当前可用能力**与**拟建设能力**分开记录，不把历史展示材料中的设想当作上线承诺。

## 2. 用户与场景

| 用户 | 主要任务 | 当前入口 |
| --- | --- | --- |
| 游客 | 探索十三市文化、浏览文化资源与公开作品 | 首页、文化库、非遗、名人、传统艺术、图库 |
| 注册用户 | 管理个人资料、收藏与作品，上传图片，使用配置后的生图服务 | 登录、个人中心、我的文化作品、AI 设计 |
| 内容管理员 | 创建、编辑、发布或撤回文化动态，并维护文化资料 | 文化动态编辑台、管理 API |

## 3. 当前范围与验收口径

以下是代码中的能力基线；端到端可用性仍依赖 Supabase 数据、迁移、账号与部署配置。

| 编号 | 能力 | 当前实现与边界 | 验收要点 |
| --- | --- | --- | --- |
| P1 | 城市文化探索 | 首页默认展示十三市文化星图和城市信息面板；配置 `VITE_MAP_STYLE_URL` 后可切换地图漫游 | 默认模式不依赖地图密钥；选择城市后显示对应档案；星图明确不作为行政区划地图 |
| P2 | 文化内容浏览 | 前端有文化库、非遗、名人、传统艺术等页面；API 提供列表、详情、分类、城市与搜索接口 | 有数据时能查询与浏览；空数据、请求失败有可理解的反馈；逐页面核对数据源与详情交互 |
| P3 | 用户账户 | API 提供注册、登录、登出、令牌刷新、资料和修改密码；个人中心路由要求登录 | 未登录访问受保护页面转到登录；登录后能读取自身资料；过期令牌按现有刷新流程处理 |
| P4 | 作品发布 | `/works` 目前支持登录后上传图片、填写标题与说明、保存并查看自己的作品 | 仅接受 JPG/PNG/WebP，单张不超过 5 MB；上传失败或保存失败显示错误；重新登录后能查到作品 |
| P5 | 文化动态编辑 | 管理员可创建草稿、编辑、发布和撤回新闻；服务端检查 `profiles.role = 'admin'` | 普通用户保存返回拒绝；管理员保存后重新读取内容一致；操作记入日志 |
| P6 | AI 设计 | 文本设计描述由前端模板生成；图像生成调用服务端接口，需有效登录及 `VOLCENGINE_API_KEY`，并受每日额度约束 | 未配置服务时给出失败提示；不将模板文案宣称为大模型生成；生成图片目前不等于自动保存作品 |

## 4. 下一阶段需求

优先级采用 P0（上线前必须处理）、P1（首轮迭代）、P2（后续探索）。是否进入开发以项目负责人确认的迭代范围为准。

| 编号 | 优先级 | 需求 | 完成标准 |
| --- | --- | --- | --- |
| R1 | P0 | 统一页面与 API 的真实能力说明 | 逐页标注真实数据或演示数据；修正与当前实现冲突的旧说明；对无后端支撑的交互不展示成功假象 |
| R2 | P0 | 完成基础部署与数据验收 | 执行两份 Supabase migration，导入必要内容，配置环境变量；在目标环境跑通游客浏览、注册登录、作品上传、管理员保存四条主链路 |
| R3 | P0 | 新闻正文安全展示 | 对管理员保存的 HTML 设定允许标签规则并在公开展示前清洗；检查现有富文本展示位置 |
| R4 | P1 | 作品上传失败后的资源清理 | 当图片上传成功但作品记录创建失败时，支持清理未关联文件；验证重复提交和重试行为 |
| R5 | P1 | 完善内容管理流程 | 定义新闻新建、审核、发布和撤回的权限及状态后，再实现管理界面与 API |
| R6 | P1 | 明确 AI 产品能力 | 决定继续使用模板文案还是接入真实文本服务；若接入，补充成本、限流、失败处理与结果标识 |
| R7 | P2 | 数据质量与运营指标 | 建立内容来源、授权、更新人和更新时间记录；定义搜索成功率、作品发布成功率等指标口径 |

## 5. 非功能要求

- **权限与隐私**：所有写操作在服务端校验身份和资源归属；服务端密钥不进入前端构建产物。公开作品图片应提示用户避免上传私密照片。
- **兼容与可用性**：桌面和移动端完成主要流程；空状态、加载中、接口失败均提供反馈；地图服务不可用时保留默认星图入口。
- **内容可信度**：城市、非遗、人物等资料应记录来源与核对方式；演示数据不得作为权威统计对外发布。
- **可维护性**：新需求同时更新 PRD、规划、相关技术文档和对应代码；旧 Spring Boot 材料仅供迁移参考。

## 6. 不在当前承诺范围

第三方登录、AI 文本大模型生成、自动内容审核、新闻完整发布流程、地图导航与精确地理测量，均尚未形成可验收的当前产品能力。若纳入迭代，应先补充用户流程、数据与权限设计。

## 7. 待确认事项

1. 首次正式交付面向演示、公开公益服务，还是持续运营？这会影响内容授权、部署和运营要求。
2. 内容数据由谁提供、核验和更新？是否有正式的城市及非遗数据源？
3. 管理员如何分配及回收权限？新闻是否需要审核与发布状态？
4. AI 生图的调用预算、用户额度及作品版权提示采用什么规则？
