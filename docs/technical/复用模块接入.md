# 复用模块接入

当前主线：Vue 3 + Vite 前端、Hono Serverless API、Supabase PostgreSQL/Auth/Storage。原 Spring Boot 实现位于 `legacy/`。

## 地图

首页 `CulturalMap.vue` 默认用 Apache ECharts 绘制十三市文化星图。点城市或下方城市索引，沿用原有文化档案面板。星图只表达城市之间的相对空间位置，**不是行政区划边界图**，不能用于精确测量或导航。这样默认模式无需高德密钥、地图瓦片或远程地图接口。

如需街道底图，在前端构建环境设置 `VITE_MAP_STYLE_URL`，值为 MapLibre 可读取的 style JSON URL。配置后首页出现“地图漫游”模式。底图瓦片、字体、样式与地理数据不是 MapLibre 仓库的一部分，需确认其授权、费用和中国境内可用性。旧高德坐标与底图坐标系可能不一致，正式发布前应逐城市核对定位；切换后还需在移动端实测渲染和加载失败回退。地图视图由组件卸载时释放。

## 前端动效

城市档案面板使用 `motion-v` 的进入动效。内容与地图选择状态仍由 `HomeView.vue` 管理。避免给所有节点叠加持续动画；移动端与 `prefers-reduced-motion` 下应重点检查视觉稳定性。

## 作品图片

在 Supabase SQL Editor 依次执行 `apps/api/supabase/migrations/001_initial_schema.sql` 与 `002_work_images.sql`。第二个 migration 创建公开的 `user-works` bucket，允许 JPG、PNG、WebP，最大 5 MB。前端 `/works` 通过 `POST /api/works/upload` 上传，再通过 `POST /api/works` 保存记录。上传接口要求有效登录令牌，并检查文件头与图片格式是否一致；文件放在以用户资料 ID 开头的目录。公开 bucket 意味着知道 URL 的人可查看图片，勿上传私密照片。

部署前实测：登录、上传、作品创建、重新登录后列表、公开图片 URL、超限和错误格式拒绝。若上传成功但创建作品失败，bucket 中可能留下未关联图片，后续应加清理任务或管理操作。

## 新闻编辑

`/admin/news` 读取现有新闻列表与详情，用 `@tiptap/vue-3` 编辑富文本正文，调用 `PUT /api/admin/news/:id` 保存。Hono 再次验证 Supabase 用户，并核对 `profiles.role = 'admin'`；普通用户无法保存。该页面只编辑已有新闻，不包括新建、审核发布或媒体库。迁移现有新闻数据并通过可信任的 Supabase 管理端指定管理员后才能使用。服务端目前保存 Tiptap 生成的 HTML；若将正文以 `v-html` 展示给公众，必须先增加 HTML 清洗和展示白名单。

## 依赖与边界

新增前端依赖：`echarts`、`maplibre-gl`、`motion-v`、`@tiptap/vue-3`、`@tiptap/pm`、`@tiptap/starter-kit`。作品上传复用后端已经安装的 `@supabase/supabase-js`。未部署地图瓦片服务，也未接入 AI 生图服务。文化内容、城市档案、审核规则与视觉设计继续由项目代码维护。
