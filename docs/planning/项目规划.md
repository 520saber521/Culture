# 江苏文化传承与创新平台项目规划

> 版本：v0.1
> 更新日期：2026-11-11
> 状态：建议执行顺序；未指定负责人和日历期限。

> 进度记录（2026-11-12）：代码层已完成作品隐私、图库发布、内容管理、举报、AI 额度和基础统计；目标环境的第三次迁移、数据导入、管理员分配及完整业务验收尚未执行。首页演示资料仍需按来源和授权核验后迁入数据库。

## 1. 规划依据

以 [PRD](../product/PRD.md) 的现状基线和需求编号为准。主线架构为 Vue 3 + Vite、Hono API、Supabase PostgreSQL/Auth/Storage；`legacy/spring-backend` 仅作迁移参考。当前仓库已有构建与 API 测试命令，但目标环境的业务数据和服务配置需要单独验收。

## 2. 阶段与交付物

| 阶段 | 对应需求 | 主要工作 | 退出条件 |
| --- | --- | --- | --- |
| A. 基线盘点 | R1 | 逐页核查数据来源、交互、空状态和错误状态；列出旧文档与代码差异 | 形成页面能力清单，所有展示/演示能力有明确标识 |
| B. 可运行环境 | R2 | 准备 Supabase 项目、执行 migration、导入内容、配置前后端环境变量与管理员 | 游客浏览、注册登录、上传作品、管理员编辑四条流程在目标环境通过 |
| C. 上线质量 | R3、R4 | 富文本清洗与展示规则；图片孤儿文件处理；移动端和异常场景检查 | 权限、富文本、图片失败恢复均有验证记录 |
| D. 内容运营 | R5、R7 | 设计新闻发布流程、内容来源字段和更新责任；确定运营指标 | 状态、角色、内容责任人与指标口径经项目负责人确认 |
| E. 创作能力 | R6 | 明确 AI 文本能力，核算生图成本与额度，设计失败和保存流程 | 对外描述与真实服务一致，额度和错误处理可验收 |

阶段顺序体现依赖关系，不代表已排定日期；B 阶段需要可用的 Supabase 项目和内容数据，D/E 阶段需要产品决策。

## 3. 近期执行清单

1. 依据路由、页面和 API 建立逐页能力清单，确认哪些页面使用真实接口，哪些仍为静态或演示内容。
2. 修订历史页面讲解与作品介绍中关于高德地图、Spring Boot 主后端、AI 文本和第三方登录等过时表述。
3. 在目标环境执行 `001_initial_schema.sql`、`002_work_images.sql`，导入最小可用文化内容并创建受控管理员账号。
4. 跑通 PRD 中 P1–P6 的实际用户流程，记录环境、结果、缺陷和复测状态。
5. 优先处理新闻 HTML 展示安全与作品上传后保存失败的清理问题，再评估公开发布。

## 4. 验收与变更规则

- 每项需求以 PRD 编号关联实现、验收结果和遗留问题；仅有页面入口或 API 代码不算端到端完成。
- 提交前运行仓库根目录的 `npm run build` 与 `npm test`；涉及权限、上传或富文本时，再做对应的目标环境手工验证。
- 新增外部服务时，在技术文档中记录配置项、权限、费用/限额、失败回退和数据处理方式。
- 需求范围或优先级变更时，先更新 PRD，再调整本规划；发布日期和负责人确认后补入，不预设虚构排期。

## 5. 主要依赖与风险

| 事项 | 影响 | 处理方式 |
| --- | --- | --- |
| 文化内容与图片来源未统一核验 | 对外信息准确性和素材使用受影响 | 为内容和素材建立来源、授权、复核记录 |
| Supabase 数据与管理员账号未准备 | 主要流程无法端到端验收 | B 阶段明确环境、迁移、数据和账号交付人 |
| 地图样式及瓦片依赖第三方 | 地图漫游可能不可用或有费用 | 默认星图保持可用；上线前核对授权、坐标和移动端表现 |
| AI 图像服务需密钥和预算 | 功能可用性与成本不确定 | 设置额度、监控、错误反馈，并验证无密钥场景 |
